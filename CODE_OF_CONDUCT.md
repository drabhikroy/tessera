# Code of conduct

## The short version

Assume the other person is working in good faith, argue about the work
rather than about the person, and say what you mean plainly.

## What is expected

Discussion here is about a program that reads networks of people, so a
fair amount of it will be about methods, and methods arguments get
sharp. Sharp is fine. The line is between a claim about the work and a
claim about whoever produced it.

Be specific. A review that says a function is wrong and says why is
useful; one that says the code is bad is not. The same holds in reverse:
if someone tells you a thing is wrong, the useful answer engages with
the reason.

Accept that not every contribution will be taken. A maintained project
says no more often than yes, and a no is about scope rather than about
the person who offered.

## What is not accepted

Harassment, insults, or attacks on a person rather than their work.
Sustained disruption of a discussion. Publishing anyone's private
information. Sexualized language or imagery. Anything that would make a
reasonable contributor decide it is not worth the trouble to keep
participating.

## Reporting

Report a problem by opening a private security advisory through the
repository, which is the only private channel this project has, or by
contacting the maintainer directly through the address on the GitHub
profile.

Reports are read by the maintainer. A report will be answered, and its
existence will not be shared with the person it concerns except as far
as answering it requires.

## Scope and outcome

This applies to issues, pull requests, discussions, commit messages, and
anywhere else the project is being represented.

The response to a first problem is usually a private word. Repeated or
serious problems lead to comments being removed, a discussion being
locked, or the person being blocked from the repository.
